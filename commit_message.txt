Port ExifTool to in-process zeroperl (WASM) via wazero

Run ExifTool without os/exec: embed zeroperl.wasm, Perl wasm32-wasi prefix
(Image::ExifTool), and exiftool.min.pl; drive the guest through wazero with WASI
and a stub env.call_host_function import.

API
- Command/CommandContext: overlay host CWD with embedded lib at /, temp dir
  writable; charset and package Arg1/Config folded into argv.
- Run/RunDebug: perl-only root plus optional workFS at /work.
- Server: compile WASM once; stay_open over pipes; splitReadyToken framing;
  Shutdown/Close with shared finalize; cmdMtx serializes Command.

Implementation
- evalModule: zeroperl_init, malloc script/argv, zeroperl_eval; treat Perl exit 0
  (sys.ExitError) as success; autoflush preamble on embedded script.
- devNullFS for /dev (no testing/fstest in library code); perlFS panics if embed
  layout is wrong.

Benchmarks
- bench_test.go: 30 benchmarks across 6 categories — cold start (Command/Run/Server),
  warm server ops, single-shot file reading, stdin image streaming, sequential
  throughput comparison, and file size/type variation (JPG/PNG/TIFF).
- benchmark-results-20260403-115330.txt: zeroperl baseline (~8s cold start,
  ~1.8ms warm Server.Command -ver, ~88ms warm JSON on 3.5KB JPEG).
- benchmark-results-orig.txt: upstream ncruces/go-exiftool (os/exec) baseline
  for comparison (~225ms cold start, ~168us warm -ver, ~7.5ms warm JSON).
- plans/benchmark-design.md: benchmark design rationale and category documentation.
